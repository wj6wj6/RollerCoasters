# 發布、備份與驗證

## 發布前

1. `pwsh -File scripts/check-all.ps1` 全部成功（等同 MSVC 與 Clang 各自 Debug／Release 的 `scripts/check.ps1 -Stage all`）。
2. 使用下列 GUI 清單驗證實際 Windows 裝置，於 PR 記錄結果。
3. 備份重要軌道檔並做一次還原驗證。
4. 需要發布新版本時先修改 `CMakeLists.txt` 的 `project(... VERSION ...)`，合併後再建立對應 `v*` tag。

## CI

repository 是公開的，GitHub 提供的標準 runner（含 Windows）不計費。CI 分成兩個 workflow，每個非 draft PR 的 push 都會兩個一起跑；只改文件（`*.md`、`docs/`）時略過：

| Workflow | 何時執行 | 內容 |
| --- | --- | --- |
| `Linux quality`（`ci.yml`，ubuntu-24.04，兩個平行的 job） | PR push、main push、手動 | 快速回饋。`linux`：`check.ps1 -Stage quick`（clang-format 22.1.8、依賴指紋、repository 規範與腳本語法）；`tests/linux/` 以 clang `-Wall -Werror` 編譯平台無關的原始碼並跑 `VersionCheck` 以外的全部 CTest 檢查（xvfb）。`win32-syntax`：`tests/linux/win32-syntax.sh` 用 MinGW-w64 對真正的 Windows SDK 標頭檢查所有檔案的語法 |
| `Windows build`（`windows.yml`，windows-2022，單一 job） | PR push、main push、`v*` tag、手動 Run workflow | 完整把關：`scripts/check-all.ps1 -Jobs 0`，即格式、MSVC `/analyze`（只跑一次）、MSVC 與 Clang 的 Debug／Release 編譯、CTest、安裝與 `--version` |

同一個 PR 或分支的新 push 會取消舊的執行，draft PR 不執行。Ubuntu 套件鏡像站有時慢到讓安裝逾時，所以兩個 Linux job 各自快取下載過的 `.deb`（`install-packages.sh --only core`／`--only mingw`，快取鍵含腳本的雜湊），安裝一成功就存檔（不必等整個 job 成功），之後的執行不經網路直接安裝；MinGW 佔下載量的大半，獨立成 `win32-syntax` job，`linux` 不必等它。PR 讀得到 main 存的快取，所以 main 跑過一次後 PR 都不必再下載。`tests/linux/stubs/windows.h` 定義了 Windows SDK 會吃掉的 `far`、`near`、`DUPLICATE` 等巨集，所以這類名稱在 Linux 檢查就會失敗；沒有 Windows 的雲端環境也能在推送前跑這組檢查（見 [development.md](development.md#linux-上的檢查)）。
Linux 檢查不是 MSVC 建置：MSVC 專屬警告、`/analyze`、連結 Win32 程式與封裝只有 Windows build 或本機 `check-all.ps1` 會驗證。

在 Windows 電腦上執行 `pwsh -File scripts/check-all.ps1` 等同 Windows build，結果表寫在 `out/check-summary.md`，可貼進 PR。
若 repository 改回私有，Actions 會依分鐘計費（Windows 比 Linux 貴數倍，額度用完時連 Linux job 都不會開始）；那時應讓 Windows build 只在 main 與手動時執行，PR 以本機 `check-all.ps1` 驗證。
Windows build 保存 `out/check-summary.md`、JUnit／CTest 日誌（14 天），以及 MSVC 與 Clang Release 已執行 `--version` 的安裝目錄 artifact（14 天）。Linux 檢查只在失敗時保存日誌（7 天）。
這是桌面應用程式，以 executable 的版本 smoke test 取代服務 healthcheck；沒有 Docker 或伺服器部署。

## 建立可交付目錄

```powershell
pwsh -File scripts/check.ps1 -Stage all -Config Release
./out/package/Release/RollerCoasters.exe --version
```

交付 `out/package/Release/`。目標機器需 Windows x64、支援 OpenGL 的顯示驅動，以及 Microsoft Visual C++ x64 Runtime（2015 之後的 v14 系列，需不舊於建置所用的 Visual Studio 版本）。
使用 Clang 封裝時加上 `-Compiler clang`，交付目錄改為 `out/package/clang/Release/`，執行期前置需求相同。
目前未包含安裝程式、程式簽章與自動更新；正式對外發布前應另行規劃。
交付目錄不含任何材質包，只有空的 `texturepacks/` 資料夾，使用者把自己的材質包放進去（見 README「材質包」）。
`--version` 驗證程式與執行期可啟動，無法驗證 GPU 呈現。

  動物、雲、熱氣球會動。三種 spline 都試一次；`Scenery` 關閉時回到平坦草地島，再開啟時恢復。
- 材質包：`World` 面板最下面的 `Textures: Built-in` 按鈕和其他按鈕同色系；清單裡的 `Open texturepacks folder` 用檔案總管打開 exe 旁的 `texturepacks/`（路徑有中文或空白也能開），把一個 zip 材質包（或資料夾）放進去，不必重開程式，再按一次按鈕清單就列出它；選它後島上的草地、石頭、樹葉等立刻換掉，秋色樹、窗戶、門、水晶、花瓣與竹子也換成材質包裡最接近的方塊（不會留下內建畫風的方塊，除非材質包真的沒有，例如沒有水的材質包），海底的沙、石頭、隧道岩壁、遺跡、海晶石閘門、珊瑚、海燈籠、海帶、海草與海鞘也全部換成材質包的圖（只有生物不換），軌道枕木是材質包的木板、鋼軌是鐵塊，風車帆布與熱氣球是材質包的羊毛，不重建島（不卡頓數秒），灰階草地與樹葉是綠色；滑鼠停在選單上顯示換了幾種貼圖；選回 `Built-in` 恢復原狀；`Open pack...` 開的是 Windows 檔案總管的「開啟」視窗，選一個不是材質包的 zip 會跳出提示並回到原本的選擇；目前用的材質包在清單裡有勾選記號，按鈕文字也跟著變；選壞掉的圖片不會跳出 FLTK 錯誤視窗。記錄使用的材質包名稱（不提交材質包本身）。
- `Grand Tour` 用三種 spline 各跑一圈：軌道沒有銳角的急彎或髮夾彎（岩山往東北出海與火山口上方的轉彎都是平順的大弧線）。
- 海底段經過沉船時：船身是木板、船頭是尖的、甲板破洞看得到船艙，船尾樓有欄杆，主桅是斷掉的短樁，船上沒有一排橫放的原木。
- `Grand Tour` 跑完一圈（約幾分鐘）：島的海岸線不是方形；雪山、瀑布峽谷與城堡、村莊、峽谷、火山都比之前大；列車不會穿過方塊；外海小島是沙岸與草地，水面上沒有黑色石塊；記錄啟動時間與幀率。
- `Grand Tour` 最後一段：列車從主島北岸出海到東北新大陸，竹林是成叢的高竹（竹竿是實心細方柱、一根一根連續、不擺動，頂上連成淡綠的葉冠；遠看不是一條條細線），竹林空地上有長滿苔蘚的叢林神殿（`Time` 調到夜晚時頂上的水晶與燈籠發光），紅樹林有氣根與垂藤、泥灘裡有水窪但軌道旁沒有水，回程經跨海峽的長棧橋，兩段路線不交叉。
- `Time` 調到約 17:45，從島西岸朝夕陽看：淺海裡看得到粉紅、紅、橘、紫、黃色的珊瑚塊，海面有金色倒影，珊瑚沒有露出水面。
- 同一圈的海底段：入水與出水時畫面切換正常，水下看得到遠處的岩石與遺跡，有光束、微粒、氣泡與各種海洋生物，
  隧道內變暗只剩水晶與頭燈，列車不會穿過方塊，水草與珊瑚不碰到鐵軌；三種 spline 都試一次。
- 關閉視窗可結束程序；記錄 Windows、GPU／驅動與輸入裝置。

## 軌道備份與還原

Load／Save 會直接讀寫指定檔案。儲存前保留原檔，尤其不要用唯一的資料副本測試新版本。

```powershell
New-Item -ItemType Directory -Force backups | Out-Null
Copy-Item -LiteralPath data/my-track.txt -Destination backups/my-track-before-change.txt
Get-FileHash -Algorithm SHA256 data/my-track.txt, backups/my-track-before-change.txt
Copy-Item -LiteralPath backups/my-track-before-change.txt -Destination data/my-track-restored.txt
Get-FileHash -Algorithm SHA256 backups/my-track-before-change.txt, data/my-track-restored.txt
```

確認雜湊相同，再於程式載入 `my-track-restored.txt`，確認控制點和畫面。
還原使用新檔名，驗證後才決定是否替換工作檔。重要備份另存其他磁碟；repository 的 ignore 不能代替備份。
若未來增加格式版本，以追加且相容舊資料的方式處理，先加入舊格式讀取與新格式往返測試。

## 回復版本與排錯

保留前一版可用的發布目錄；新版本異常時關閉程式，使用前一版 executable 與已驗證的軌道備份。
建置失敗先確認使用 x64 MSVC／clang-cl 與 `tools.json` 指定的原生工具版本。Clang 模式先執行 `scripts/setup-tools.ps1 -WithClang`。不要混用 MinGW 或其他架構的 libraries。
CI 失敗保留 test-results artifact；日誌與 issue 附件避免包含使用者私密路徑與軌道內容。
