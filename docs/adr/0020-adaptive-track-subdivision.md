# ADR 0020：鐵軌用自適應細分取樣

日期：2026-11-25
狀態：採用

## 背景

鐵軌是沿中心線的一串直段（四個面的 quad strip）。原本每個控制點段固定取 48 點（`TrackArcTable` 的 u 等分），所以 `Grand Tour`（62 點、約 6000 單位長）不論直線或急彎都是 2977 點：長直線浪費，而 Cardinal 最急的彎一段直線仍轉 4.4 度。期末專題清單把 P3 進階項 Adaptive subdivision 列為待做，要能展示取樣差異。

## 決策

- 新模組 `src/TrackSampling.*`（沒有 OpenGL）：`sampleTrackUniform()` 是原本的固定取樣；`sampleTrackAdaptive()` 每個控制點段從一整段開始，只要還不夠直就對半切：
  - 誤差：段內 1/4、1/2、3/4 三點離弦（兩端連線）最遠超過 `maxError`（0.02 單位，鐵軌寬 0.24 的十二分之一）。
  - 轉角：四條 1/4 弦的方向轉角加總乘 4/3（四條弦只看得到 3/4 的轉向）超過 `maxTurnDegrees`（2 度）。用加總而不是比兩端方向，S 彎中點落在弦上時也抓得到。
  - 一段最多切 9 次（512 份），尖點不會無限細分。
  - 每個控制點都是取樣點；Linear 的轉角（相鄰兩段方向差超過兩倍轉角上限）兩側各補一個距離 1/48 的點，讓轉角處斜接的鐵軌框架只影響很短一段，和固定取樣一樣。
- `TrackMesh` 的鐵軌用自適應取樣（`Track` > `Adaptive: ON`，預設）或固定取樣（`OFF`）；切換時重算網格。枕木仍依弧長表等距擺放，弧長表維持每段 48 點等分：查表是在兩筆之間對 u 線性內插，需要短的區間，這是查表精度問題，不是鐵軌形狀。
- `Track` > `Samples: ON` 在畫面最上層（不做深度測試，隧道裡也看得到）畫出取樣：青色中心線、每個取樣點一條橫過兩條鐵軌的黃色橫線與紅點，深色描邊，像方塊遊戲的除錯線。`Track` 畫面、F3 與 `--benchmark` 報告寫出取樣數與固定取樣的點數。
- `--adaptive on|off`、`--samples on|off` 讓截圖與效能測試能切換。

## 結果

`Grand Tour` 的取樣數（固定都是 2977 點）與一段直線最大轉角：

| 樣條 | 自適應 | 最大轉角（固定 → 自適應） |
| --- | --- | --- |
| Linear | 179 | 0.07 → 0.04 度 |
| Cardinal | 1931 | 4.40 → 1.99 度 |
| Cubic B-Spline | 1665 | 2.33 → 2.00 度 |

點數少了 35–94%，最急的彎反而更圓滑。四點的起始軌道整圈都在轉彎，自適應是 257 點（固定 193 點），因為彎道要切到 2 度以內。

## 取捨

- 對半切讓點數以二的次方增加，同樣的誤差上限下會比最佳化的分割多一些點；換來的是簡單、可預測，且每個控制點必定是取樣點。
- 取樣只在控制點、樣條或開關改變時重算（與網格快取同一時機），每次多花幾千次曲線求值，比畫一幀便宜得多。
- 取樣點的除錯線用記憶體中的 vertex array 每幀畫，只在 `Samples` 開著時才花這份工夫。
