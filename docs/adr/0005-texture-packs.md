# ADR 0005：執行中切換材質包，讀取使用者自己的資源包

日期：2026-11-18
狀態：採用

## 背景

島上的方塊貼圖原本全部寫死在程式裡（`LandTextures` 程序繪製）。使用者希望能像方塊遊戲一樣切換材質，之後也能匯入從網路下載的材質包。網路上的材質包大多是方塊遊戲資源包的格式：一個 zip，圖片在 `assets/minecraft/textures/block/`。

## 決策

- 新增 `TexturePack` 模組：在執行中讀取使用者放進 `texturepacks/`（exe 旁，建置與安裝時建立空資料夾；另外也找工作資料夾的 `texturepacks/` 與 `data/texturepacks/`，`main()` 啟動時已切到 exe 的資料夾，所以通常是同一處）的資料夾或 zip，或由 `Open pack...` 選取的檔案。程式本身不附帶、不散布任何第三方材質包或其圖片，內建貼圖仍是程序繪製。
- 支援兩種格式：本程式自己的 `textures/<名稱>.png`（每種貼圖都能換），以及資源包的 `block/`（新）與 `blocks/`（舊）資料夾，以方塊名稱對照表對應到島上的貼圖。灰階的草地與樹葉依方塊遊戲的慣例染色；動畫取第一格；實心方塊補滿透明處。
- 造景盡量只用材質包有的方塊：對照表每一列依序列出替代方塊（`名稱@顏色`），資源包沒有島上那種方塊時，用最接近的方塊代替並染成該有的顏色（秋色樹＝染橘的橡樹葉、窗戶＝材質包的玻璃（保留透明度）、水晶＝海燈籠、舊材質包的紅樹林與櫻花＝染色橡樹葉）；竹子由竹子方塊與竹葉排成程式畫竹子的版面；水取材質包的水染藍、透明度沿用內建。材質包真的沒有的才維持內建。
- zip 解壓用自己寫的 DEFLATE 解碼器（`ZipArchive`，依 RFC 1951），不新增第三方程式庫，也不需要更新 `vendor-lock`。內附 FLTK 雖含 zlib 靜態庫，但沒有附 zlib 標頭，自行宣告其結構容易與版本不合。PNG 解碼用內附 FLTK 的 `Fl_PNG_Image`（記憶體版建構子）。
- 換材質包時把新圖片寫進原本的 OpenGL 貼圖名稱（`PixelArt::uploadInto()`），顯示清單不必重建，切換是即時的。
- 解碼壞掉的圖片時暫時換掉 `Fl::error`／`Fl::warning`，避免 Windows 上 FLTK 預設跳出訊息方塊；壞圖片只是不採用。

## 取捨

- 換島上（`LandWorld`）與海底（`OceanWorld`，以 `Pack::standIn()` 依它自己的方塊名稱表取圖）的貼圖；軌道的枕木與鋼軌、風車與熱氣球也換；列車、生物、天空與雲不換，之後可依同樣方式擴充。
- 替代方塊只換貼圖，不改島上方塊的種類與形狀，所以切換材質包仍然不必重建島；代價是替代方塊的外觀只是接近（例如門是整格方塊，貼的是橡木門下半部）。
- 不支援 zip 加密、ZIP64、分割壓縮檔、資源包的模型（`models/`）、`.mcmeta` 動畫與 CTM 等延伸格式；方塊形狀仍由程式決定。
- 資源包的方塊名稱只是檔名對照，用來讀取使用者自己提供的檔案；授權由各材質包的作者決定，使用者需自行遵守。
