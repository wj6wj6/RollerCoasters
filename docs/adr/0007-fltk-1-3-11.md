# ADR 0007：內附 FLTK 由 1.3.5 升級到 1.3.11

日期：2026-11-19
狀態：採用

## 背景

程式常常崩潰。課程附的 FLTK 1.3.5（2019）有已知的記憶體錯誤，例如 `src/Fl_Menu.cxx` 的 `backward()`：下拉選單打開後滑鼠離開清單，目前選項 `menu_number` 變成 -1，再按 Backspace 或上鍵時它照樣讀 `pp.p[-1]`，讀到垃圾記憶體而崩潰。`World` 面板的材質包按鈕（`Fl_Menu_Button`）會走到這段。用真的滑鼠很容易碰到，模擬點擊很難重現。1.3.8（Linux 檢查用的系統 FLTK）也沒修；1.3.11 在開頭加了 `if (menu<0) return 0;`，1.4 也已修正。

1.3.5 到 1.3.11 之間還修了許多其他崩潰與越界讀寫，API 相同。

## 決策

- 用 FLTK 官方 1.3.11 原始碼（`fltk-1.3.11-source.tar.gz`，SHA256 `92805abc84505e3e7e27aec775ab0754ecb4182fe2d8ff2a9d568ccdcb2811ac`）重新編譯內附的 `include/FL` 與 `lib/{Debug,Release}/fltk*.lib`，檔名與元件（`fltk`、`forms`、`gl`、`images`、`jpeg`、`png`、`z`）不變，`CMakeLists.txt` 的連結設定不必改。
- 編譯設定：靜態庫、`/MD`／`/MDd`（與原本相同）、內附 zlib／libpng／libjpeg、`/utf-8`（中文 Windows 的 950 字碼頁會誤讀 FLTK 的 UTF-8 原始碼）。Debug 以 `/Z7` 把除錯資訊放進 `.lib`，Visual Studio 的呼叫堆疊可以看到 FLTK 內部的函式與行號；因此移除原本為「Debug FLTK 沒有 PDB」而設的 `/IGNORE:4099`。
- `scripts/build-fltk.ps1` 可重做這次編譯（下載、驗證雜湊、設定、建置、複製），之後執行 `check.ps1 -Stage vendor-lock` 更新指紋。
- 介面仍是 FLTK。使用者希望之後整個換成自己畫的介面（像方塊遊戲那樣以 GLFW 開視窗、在 OpenGL 裡畫面板），那是另一件工作；這次先讓現有版本不再因 FLTK 的已知錯誤崩潰。

## 後果

- 這份庫用 MSVC 19.44（Visual Studio 2022 17.14）編譯。連結 RollerCoasters 的 MSVC 必須是同一版或更新（VS 2022 17.14 以上或 VS 2026）；較舊的 Visual Studio 需要先更新，或以 `build-fltk.ps1` 用自己的版本重新編譯。clang-cl 使用 MSVC 的連結器，規則相同。
- Debug 的 `fltkd.lib` 約 15 MB（原本 7.7 MB），因為含除錯資訊。
- Linux 檢查仍用系統的 FLTK 1.3.8，不受影響。
