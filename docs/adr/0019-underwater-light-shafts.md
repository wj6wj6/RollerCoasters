# ADR 0019：水下的光：光柱跟著焦散、折射的陽光、真實的 Snell 窗

日期：2026-11-24
狀態：採用

## 背景

水下的光柱（`PostEffects` 的 `kShaftsFragment`）看起來很假：從太陽方向射出一大把細而亮的白線，像鏡頭星芒，水下各個方向都一樣密，一路亮到海底。往上看時還有兩個太陽：天空的太陽畫在真正的方向，水面的閃光畫在折射後的方向，光柱集中在前者。

它也很貴。半解析度、每個像素 36 步，每一步算三層 cell（Voronoi）噪聲（共 27 個 cell，每個都有 `sin`）再查一次 shadow map。使用者筆電（RTX 5060，2560x1559 全螢幕）水下一幀 16.5 ms，關掉光柱是 7.1 ms；改成四分之一解析度是 9.5 ms，再減成 18 步是 8.4 ms，但解析度降到 640x390，比 480p 還低。

## 決策

- 光柱的樣子改用一張預先算好、可以無縫重複的 128x128 圖樣（`makeShaftPattern()`，`GL_RG8` 加 mipmap）：紅色是細的 cell 邊線，綠色是寬而柔的同一組邊線。每一步在「太陽光穿過水面的那一點」查兩次，兩份圖樣以不同大小、方向慢慢漂移，交會處就是被波浪聚焦的光束，會慢慢變形移動。
- 越深越柔：靠近水面時以細圖樣為主、對比高；越深越換成寬圖樣、對比降低，到海底附近只剩均勻的微光，光柱不會像柱子一樣插在海底。
- 散射偏向前方（Henyey-Greenstein，g = 0.6）加一點均勻散射：朝太陽看光柱明顯，背對太陽很淡。光柱帶水的藍綠色。
- 光照進水會折射（Snell，水 1.33）：光柱、水中的光暈都沿折射後的方向；水下時天空的太陽與月亮也畫在折射後的方向，和水面閃光、光柱交會點是同一個，只剩一個太陽。陰影仍用原本的 shadow map。
- 解析度維持半解析度，步數 36 → 28，迴圈不再提早結束，讓圖樣的 mip 層正確（遠處自動變柔，不閃）。頭燈光錐不變。

## 第二輪（同一個 PR，看過 PR 版本的截圖後）

使用者用 PR 版本截圖給 Gemini 評，指出：從水底很平的角度往上看仍清楚看到雲與山（水面像一層藍色玻璃）；光柱與影子方向對不上；焦散太糊、深淺都一樣；畫面發灰、近處珊瑚太鮮豔。對照程式：Snell 窗是 2026-11-20 刻意加寬的（當時窗外只有一片平的藍色，看起來像蓋子）；焦散有乘陰影，但陰影用的是沒折射的陽光。

- 水面從下往上看：窗是真實的約 48.6°（`refract()` 超過臨界角就是零），窗內每個像素沿折射後的方向去拿天空：方向落在畫面內、而且那裡是水面上的東西，就取畫面的顏色，否則用天空的漸層；水面的波浪讓窗的邊緣和窗內的雲、島一起扭動。透射量用水到空氣的 Fresnel（以空氣側的角度算），所以靠近邊緣自然轉成鏡面。窗外是全內反射：鏡面本身是水色，依每個波面反射的方向明暗（往水平方向反射的較亮、往深處的較暗），所以波浪仍看得見；再用 screen space reflection 疊上下面的海底與遺跡（反射方向用較平的法線，免得碎成雜點；顏色和水色混合，代替來回路程的霧）。貼著水面往遠處的反射會把遠方的東西拉成直條紋，所以只保留往下的反射。
- 攝影機在水下時，shadow map 沿折射後的方向畫；照明 shader 在水面下的點用折射後的方向算 `n·l` 與焦散的投影，光柱的遮擋查同一張 shadow map。影子、焦散、光柱三者一致。折射只讓光變陡、不會變多：水平地面上每單位面積收到的光和水面相同（扣掉約 3% 反射），所以水下的陽光乘上「真實方向的 y／折射方向的 y」，沙地不會因為光變陡而變亮。代價：攝影機在水下時島上的影子方向略錯（那時看不到）；攝影機在水上時，水下的點用折射方向打光、影子仍用真實方向。
- 焦散 `caustics()` 改傳回 RGB：細胞邊線用 `exp(-edge / w)`，除以它的平均值；兩張大小、方向不同的網除了相加，更多是相乘，亮光集中在交會處成為亮結與亮帶，不是一張均勻的網；再乘上一層緩慢移動的大尺度噪聲，有的區塊強、有的區塊淡。線寬 w 隨水深與離攝影機的距離變寬，對比隨兩者降低；紅、綠、藍的線寬是 0.8、1、1.25 倍，邊緣略帶藍色（色散）。平均約 0.92，沙地不會因此整體變亮。
- 水下的環境光不再比水上亮（tint 從 0.8/1.3/1.6 改為 0.55/0.95/1.2），暗面與影子更深；視線方向的紅光吸收 0.0125 → 0.017，近處的暖色多吸收一點。

## 第三輪：光柱跟著焦散（同一個 PR）

使用者看了第二輪仍覺得光柱「像貼圖一樣」。原因：第一輪的圖樣是固定的貼圖，靠整張平移產生變化，所以光柱是一整片細線一起往同一個方向滑；而且它和海底的焦散毫無關係，光柱落下的地方沙上沒有對應的亮處。

- 每幀畫一張焦散圖（`kCausticMapFragment`，1024x1024、RGBA16F、mipmap），涵蓋攝影機附近 400x400 的水面（中心偏向太陽光照下來的方向，且以整個 texel 移動，免得網格隨攝影機抖動）。紅色是海底用的同一張細焦散網（`causticWeb()`），綠色是強弱區塊（`causticPatch()`），藍色是新的「大浪聚光點」（`causticSwell()`：兩張約 20 單位一格的粗網的交會處，平均 1）。
- 光柱每一步在「這道陽光穿過水面的那一點」查這張圖，所以光柱就是被波浪聚焦的那束光：主要是大浪聚光點延伸下來的光柱，靠近水面時再帶一點細網的條紋。越深查越模糊的 mip 層、對比越低。聚光點的值取平方（除以平方的平均 4.1）：光集中在少數幾道亮柱，柱間的水比較暗。不取平方時，一條視線穿過七、八根柱子，加起來接近均勻，筆電上看起來像整片變亮的霧。
- 海底的焦散也乘上同一個 `causticSwell()`（權重 0.3，遠處淡出），所以每道光柱落地的地方沙上比較亮，兩者對得起來。照明 shader 從焦散圖的藍色讀它（不在每個像素重算兩張粗網：筆電上那樣做整幀多 2.2 ms，大多在海底），所以焦散圖在畫場景之前就畫好（`PostEffects::drawCausticMap()`，經 `LightingFrame::causticMap` 傳給照明）。攝影機在水上時沒有這張圖，水下的點不乘它。
- 使用者看了仍覺得像貼圖，尤其是光柱和水面的接縫，而且整體像複製貼上。原因：光柱從水面那一層就是全對比，從遠處斜看時，水面下薄薄一層的光柱就是焦散圖本身的平面圖樣；每道光柱又都一樣粗、一樣亮。改成：剛進水時光還是均勻的，波浪要往下幾個單位才把光聚起來，所以每道光柱從水面下 1.5–8.5 單位（每道不同，由焦散圖 alpha 的慢速雜訊決定）才漸漸成形，很深處對比再降一點；同一個雜訊讓一部分光柱查較模糊的 mip 層（寬而柔）、一部分維持細而亮；強弱區塊（綠色）對比權重加大。筆電上這樣光柱太淡，所以光柱的明暗再放大 1.7 倍（柱間更暗、柱內更亮，平均不變），每一步的取樣位置再隨位置加一點慢慢變化的偏斜（約 4°），相鄰光柱不再完全平行。
- 圖樣全部是在原地變形（cell 的點在原處繞小圈），不會整片平移。

## 取捨

- 每一步從約 27 個 cell 的噪聲運算變成一次貼圖查詢，主要成本剩 shadow map 查詢。多出來的是每幀畫焦散圖（1024x1024，每個 texel 四張 cell 網）與它的 mipmap，以及照明 shader 在水下多查一次貼圖。Linux 軟體繪圖（llvmpipe，1280x800）整幀從約 880 ms 降到約 470 ms；真正的 GPU 數字以筆電的 `--benchmark` 為準。
- 焦散圖只涵蓋攝影機附近 400x400；邊緣 5% 內光柱淡成均勻的光，那時已在霧裡。
- 水面下的鏡面多了一次 screen space reflection（30 步），抬頭看水面時才大面積執行。
- 焦散（和光柱）仍是程序化的網，不是從水面波浪的法線算出來的；水面的波和水下的亮處不是同一組。
